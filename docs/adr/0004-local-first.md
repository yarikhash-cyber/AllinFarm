# 0004. Спершу локально, ті самі контейнери, що й на сервері

- Статус: прийнято власником проєкту
- Крок плану: 3

## Контекст

Власник вирішив не купувати сервер, доки робоча версія не прийнята. Результат кожного кроку він відкриває на своєму комп'ютері з Windows.

## Рішення

1. Уся система описана в одному `compose.yaml`: база, API, сайт з Caddy, Mailpit.
2. Локально запускаються ті самі образи й ті самі налаштування Caddy, що потім поїдуть на сервер. Відрізняються лише змінні середовища.
3. Для Windows є `start.cmd` і `stop.cmd`: подвійний клік запускає й зупиняє систему.
4. Листи системи локально не виходять назовні: їх ловить Mailpit.

## Наслідки

- Хостинг пізніше = ті самі контейнери на сервері плюс домен, HTTPS і справжня пошта. Переробок коду немає.
- Не можна додавати кроки, які працюють лише на одній машині.

## Як перевіряється

CI на кожну зміну виконує `docker compose up --build` і перевіряє, що сайт і API відповідають.
